# kotobad 価値向上戦略メモ（2026-03-29）

## 1. このメモの目的

本メモは、`kotobad` の価値を Discord とどう差別化するかについての議論を整理し、今後の実装判断の基準を明確にするための記録です。

## 2. 背景と問題意識

- 出発点は「バドミントン好きが集まり、熱い議論をいつでもできる場を作りたい」。
- 開発を進める中で「この用途だけなら Discord で十分ではないか」という違和感が増加。
- 現状の課題は「汎用チャット機能を積むほど Discord と同質化してしまう」点。

## 3. 議論の流れ（時系列）

### 3.1 初期仮説

- 「高速雑談」単体では Discord 優位を崩しにくい。
- 差別化は、会話を**蓄積・再利用できる知識**に変換できるかで決まる。

### 3.2 クリップ論点

- 反論: クリップ共有は Discord でも簡単にできる。
- 再整理: 優位性は「動画を貼る行為」ではなく、`入力の手間` と `文脈付与` と `再検索性`。

### 3.3 Discord 連携案の扱い

- 一時的に「Discord を入口にする案」が出たが、最終的に**Discord 連携はしない**方針に。

### 3.4 バドミントン特化の方向性

- 汎用チャット競争を避け、競技特化に寄せる方向で合意。
- 特化対象: 試合文脈、戦術タグ、論点テンプレ、試合単位の振り返り。

### 3.5 ニュース運用

- 「ニュース自動投稿」は検討したが、差別化が弱くなる懸念あり。
- 最終判断: **自動投稿はやめる**。運営者がニュースを読んで感想付きで投稿する。

### 3.6 ライブ体験

- 「深い議論」だけでなく「試合を見ながらライブチャットしたい」要求を明確化。
- 既存資産（DO + WS + チャットUI + ライブスコア表示）を活かし、低コスト実装が可能。
- ただしライブチャット単体では Discord 優位は崩せないため、ライブ後の資産化を必須条件に設定。

## 4. 現時点の中核方針（採用）

### 4.1 価値仮説

kotobad の価値は次の2点を同時に満たすことで成立する。

1. 観戦中に盛り上がれるリアルタイム体験
2. 試合後に見返して使える知識資産

### 4.2 差別化の定義

Discord の代替ではなく、以下の独自価値を提供する。

- 試合文脈つきチャット（スコア・局面・選手情報と一体）
- 論点が残る構造（テンプレ、タグ、要約）
- 試合単位での再検索・再利用

## 5. 非採用または保留の案

- Discord 連携前提（非採用）
- ニュース自動投稿中心運用（非採用）
- 汎用チャット機能を増やして競争する方針（非採用）

## 6. 優先実装案（低コスト順）

1. **試合情報パネルの固定表示**  
   ライブスコア、過去対戦、試合状況を常時表示。

2. **チャットテンプレート導入**  
   例: 「今の分岐点」「戦術メモ」「判定/流れ」。

3. **スコアイベントの自動挿入**  
   例: `G2 18-18`、インターバルなどをシステム投稿。

4. **試合終了後AIサマリー**  
   チャット加速ポイント、主要論点、代表コメントを整理。

5. **見返し導線**  
   試合ページに要点・盛り上がり区間・代表コメントを残す。

## 7. 成功判定の観測指標（案）

- ライブ中: 投稿率、テンプレ利用率、同時参加数
- 試合後: サマリー閲覧率、再訪率、要約経由の再コメント率
- 蓄積価値: タグ検索利用率、過去試合参照率

## 8. 現在の結論

- `kotobad` は「汎用チャット」ではなく、**バドミントン特化の観戦・議論ナレッジ基盤**を目指す。
- ライブチャットは入口として継続する。
- 真の差別化は、終了後も価値が残る設計（構造化・要約・検索）で作る。
